# 타깃 선정 기준 — 새 파이프라인

CEO 지시 (2026-11-11): 운영 라인은 별도 창으로, FLOOR 는 병행, **이 라인은
타깃을 갈아끼운 새 파이프라인의 후보를 도출한다.**

기준을 **측정 전에** 적는다. 결과를 보고 문턱을 옮기면 선정이 아니라 합리화다.

---

## 0. 왜 타깃을 바꾸는가

EPAS1 은 후보가 나쁜 것이 아니라 **벤치마크로 실격**했다. 2026-11-07 에
원인을 확정했다 — decoy 생성 규칙이 아니라 **활성군 자체**다.

| | EPAS1 고정본 실측 (2,160개 / 활성 60) |
| --- | --- |
| 활성 상호 유사도 중위 (NN Tanimoto) | **0.7945** |
| 0.6 이상 유사체를 가진 활성 비율 | **86.7%** |
| 0.8 이상 | 46.7% |
| 활성 Murcko 골격 수 | 22종 |
| 기억 베이스라인 nEF1% / AUC / BEDROC | **1.000 / 0.9637 / 0.9549** |
| 게이트 | **PASS 3/3** |

골격이 22종인데도 실격이라는 점이 중요하다. **"한 시리즈"는 골격 수가
아니라 유사도 수준의 문제다.** 골격만 세면 통과시켰을 것이다.

단백질도 구조도 도킹도 없이 "활성끼리 닮았다"만 세는 방법이 게이트를
3/3 으로 통과하는 벤치마크에서는 **도킹이 작동하는지 물을 수 없다.**

---

## 1. 합격 조건

네 가지를 모두 만족해야 후보다. 하나라도 어긋나면 음성 결과로 기록하고
넘어간다.

| | 조건 | 문턱 | EPAS1 |
| --- | --- | --- | --- |
| **C1** | 기억 베이스라인이 게이트를 통과하지 **못할 것** | 3개 지표 중 2개 미만 | PASS 3/3 → 실격 |
| **C2** | 활성군이 한 덩어리가 아닐 것 | 중위 NN < 0.45, 0.6 이상 비율 < 0.40 | 0.795 / 0.867 → 실격 |
| **C3** | 비활성이 **실측**일 것 | 추정 decoy 금지 | 측정 비활성 0개 → 실격 |
| **C4** | 도킹 가능한 구조가 **2개 이상** | 치료군·대조군 양팔용 홀로 구조 | (해당 없음) |

### 문턱을 이렇게 잡은 근거

**C1 이 본 조건이고 C2 는 그 원인을 보는 창이다.** C1 만으로 거를 수
있지만, C2 가 없으면 왜 통과했는지 설명하지 못한다.

중위 NN 0.45 는 EPAS1(0.795)과 M1 무스카린(0.264, 10-29 실측) 사이에
둔 값이다. 양쪽 실측 사이의 중간이지 문헌 값이 아니다 — **임의 선택임을
명시한다.** 측정이 쌓이면 다시 잡는다.

**C3 이 타깃 풀을 정한다.** 추정 decoy 를 쓰면 Tanimoto 상한이 다시
들어와 지금 재려는 바로 그것을 가린다. 그래서 1차 풀은 TDC Butkiewicz
HTS 셋이다 — 비활성이 추정이 아니라 실제로 시험해 음성으로 나온 화합물이다.

**C4 는 마지막에 본다.** 구조가 있어도 C1~C3 가 깨지면 쓸모가 없고,
구조 확인은 비싸다. 순서를 바꾸면 헛돈다.

## 2. 재는 방법

`scripts/screen_targets.py`. 타깃마다 두 가지를 낸다.

- **활성 전수의 응집도** — 타깃의 성질은 전수에서 나온다
- **EPAS1 과 맞춘 부분표본** (2,157 / 활성 60) 의 기억 베이스라인 —
  n 과 활성 비율이 같아야 EF 천장이 같고, 그래야 숫자를 나란히 놓는다

지문은 SieveStack 과 동일한 Morgan radius=2, fpSize=4096 을 쓴다. 다르면
외부 숫자와 비교가 안 된다.

**잣대 검증 완료.** 이 스크립트를 EPAS1 고정본에 돌려 위 표의 수치가
그대로 재현되는 것을 확인했다(nEF1% 1.000, AUC 0.9637, 중위 NN 0.7945).
새 타깃 수치는 EPAS1 과 같은 자로 잰 값이다.

---

## 3. 이 선정이 바꾸지 않는 것

- 게이트가 PASS 하지 않으면 후보 화합물을 보고서에 올리지 않는다
- 대외 보고는 치료군과 대조군을 함께, 대조군을 편향 없는 하한으로
- 기억 베이스라인을 같은 표에 나란히 싣는다
- 음성 결과도 결과다 — 떨어진 타깃과 이유를 함께 적는다

타깃을 바꾸는 것은 **벤치마크를 고치는 일**이지, 보고 규율을 느슨하게
하는 일이 아니다.

### 네 조건을 모두 통과한 타깃 — 2종

**오렉신1 수용체(HCRTR1)** 와 **M1 무스카린 작용제(CHRM1)**.

벤치마크 청결도는 M1 작용제가 근소하게 낫고(AUC 0.576 대 0.619),
**구조는 오렉신1 이 압도적이다**(X선 홀로 14개 대 5개, ≤3 Å 11개 대 5개).

구조 선택이 상위권 enrichment 의 75% 를 움직인다는 것이 우리 간판
측정이므로, **그 측정을 제대로 하려면 구조가 여러 개 필요하다.**
→ R&D 권고는 **오렉신1 수용체**, 차순위 M1 작용제.

### 함께 나온 것 — 게이트 EF1% 문턱이 헐겁다

기억 베이스라인만으로 45회 측정(9타깃 × 5씨앗) 중 **EF1% ≥ 5.0 을 41회
(91%) 돌파**한다. AUC 44%, BEDROC 51% 와 대비된다.

활성 60개 / 2,157개에서 EF1% 천장은 약 35.95 이므로 문턱 5.0 은 **천장의
14%** 다. 단백질도 구조도 없이 활성끼리의 닮음만 세는 방법이 거의 항상
넘는 문턱은 변별하지 못한다.

→ 제안: 게이트의 `ef1` 절대 문턱을 **nEF1% 기준으로 바꾼다.**
이 변경은 운영 라인 게이트에도 함께 적용돼야 하므로 CEO 결정이 필요하다.

### 탐침에서 잡은 결함 — 해소 (2026-11-13)

구조 탐침이 두 번 조용히 틀린 수를 냈다. 1차는 나트륨 이온을 리간드로
세어 오렉신1 홀로를 부풀렸고, 2차는 리간드 필드를 잘못 읽어 KCNQ2 를
0으로 깎았다. 둘 다 표만 보면 그럴듯했다. 지금은 리간드가 있다고 알려진
항목 셋으로 매 실행 자체 점검을 돌린다.

3차(`43041991727`)는 자체 점검이 **실패**로 찍힌 채였다. 원인은 점검
항목으로 고른 7CR0 에 비중합체 엔티티가 없었던 것이고 탐침은 정상이었다 —
내 항목 선정이 틀렸다. 항목을 8IZY 로 바꾸고 cryo-EM 집계 버그('EM' 을
'ELECTRON' 으로만 찾아 전부 0 이 됐다)를 함께 고쳐 4차를 돌렸다.

**4차 `43382254991` — 자체 점검 3/3 통과.** 3차와 대조한 결과:

| 항목 | 3차 대비 |

| PDB 총 · 홀로 · X선 · ≤3 Å · C4 판정 | **전부 동일** |
