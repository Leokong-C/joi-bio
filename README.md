>
> 이 저장소의 `exp/**/candidates_top20.jsonl` 과 `docked_all.jsonl` 은
> **검증을 통과하지 못한 중간 산출물**입니다. 우리 자신의 감사 결과:
>
> - 학습도 단백질도 구조도 쓰지 않는 **기억 베이스라인(AUC 0.9637)이
>   도킹(0.7717)을 이깁니다.** 이 벤치마크로는 도킹이 작동한다는 것을
>   증명할 수 없습니다 — `scripts/leakage_audit.py`
> - `candidates_top20.jsonl` 의 화합물은 같은 실행에서 **decoy(음성)로
>   라벨된 것들**입니다. 후보와 음성을 같은 집합에서 뽑던 시기의 산출물입니다
> - 구조 선택 편향 재측정은 **두 번 실패**했고(10월 라이브러리 결함,
>   11월 timeout), 간판 숫자 "상위권 enrichment 의 75%" 는 아직 **예비치**입니다
>
> 여기 있는 화합물은 전부 공개 ChEMBL 화합물이고 신규 구조가 아닙니다.
> 치료 효과를 시사하지 않으며, 어떤 결합 주장도 실험으로 확인된 바 없습니다.
>
> 자세한 것은 `docs/purpose.md`(목적 점검 1~5차)와 `docs/context-of-use.md`.

AI 효소 설계와 정제 공정 설계를 함께 제공하는 회사를 목표로, 공통 코어 위에
세 모듈을 쌓는다. 지금 구현된 것은 코어와 저분자 결합 모듈이다.

```
core/                    세 모듈이 공유하는 자산
  structure/             구조 조회, 체인 선택, 포켓 정의
  validation/            ★ 검증 게이트 (EF1% / AUC / BEDROC / 벤치마크 회수)
  report/                보고서 생성
modules/
  small_molecule/        ① 저분자 결합 — 구현 완료
  enzyme_eng/            ② 효소 공학·공정 — 스펙만
  protein_design/        ③ 항체·바인더 — 스펙만
```

`core/`가 핵심 자산이다. 특히 검증 게이트는 저분자든 효소든 항체든 "우리 예측이
실제로 맞는가"를 묻는 같은 질문이라 모듈이 바뀌어도 그대로 재사용된다.

## 두 줄기 — 파이프라인과 검증 층

이 저장소에는 목적이 다른 두 줄기가 있다. 한쪽만 보면 다른 쪽을 놓친다.

| 줄기 | 묻는 것 | 어디 |
| --- | --- | --- |
| **파이프라인 (운영)** | 무엇이 결합하는가 — 신장 타깃 10개 스크리닝 | `exp/EPAS1/` · `exp/MET/` · `core/` · `.github/workflows/` |
| **검증 층 (연구)** | 그 숫자 중 얼마가 인공물인가 | **`exp/FLOOR/`** (FLOOR) |

검증 층의 결론이 파이프라인의 보고 규율을 정한다 — 대조군 병기, nEF1% 사용,
기억 베이스라인 동시 보고가 전부 거기서 나왔다. 들어가는 문은
[`exp/FLOOR/README.md`](exp/FLOOR/README.md)다.

요약하면, CASF-2016 코어셋 285개에서 **결합을 전혀 모르는 널 모델(R 0.547)이
AutoDock Vina(0.502)와 Vinardo(0.428)를 둘 다 이긴다.** 널을 제거하고 남는 고유
기여는 Vina가 ΔR² 0.041뿐이다. 그리고 남은 여지는 모델이 아니라 분할이 정한다 —
같은 특징·같은 모델로 교차검증 분할만 바꾸면 포켓 조성의 R이 0.241에서 0.509로
뛴다. 포켓 조성은 결합을 설명하는 게 아니라 타깃 조회 키로 쓰인다.

## 이 저장소가 지금 하는 일

**가상 스크리닝 결과를 얼마나 믿을 수 있는지 재는 것**이 현재의 주된 산출물이다.
후보 화합물 발굴은 멈춰 있다 — 아래 "원안과 달라진 점" 참조.

같은 라이브러리를 두 수용체 구조에 도킹한다. 하나는 벤치마크와 유사도가 높은
구조(치료군), 하나는 닮지 않은 구조(음성 대조군)다. 두 팔의 차이가 **구조를
잘 골라서 생긴 몫**이다.

EPAS1에서 잰 값: 치료군 EF1% 32.682, 대조군 8.170, 짝지은 차이 +24.512
[17.05–34.10], p<0.0005 → **BIAS_LIKELY**. 상위권 순위의 75%가 구조 선택에서
나왔다.

## 검증 게이트

| 판정 | 조건 |
| --- | --- |
| INSUFFICIENT | 활성 10개 미만 — 지표가 나와도 통계적으로 무의미 |
| INVALID | 활성 비율이 높아 EF 임계값 도달 불가 — 라이브러리 재구성 필요 |
| ABSTAIN | **대조군이 없다 — 판정하지 않는다** |
| PASS | 절대 문턱 2/3 + 대조군 대비 유의한 우위 + 벤치마크 회수 1개 이상 |
| FAIL | 그 외 |

### 2026-10-23 개정 — 왜 절대 문턱만으로는 안 되는가

EPAS1 음성 대조군(3H82, 벤치마크 유사도 0.0714)이 **세 문턱을 전부 넘었다**.
EF1% 8.170 > 5.0, AUC 0.7161 > 0.70, BEDROC 0.3004 > 0.30. 벤치마크와 무관한
구조가 통과하는 문턱은 문턱이 아니다. 게다가 AUC는 구조 선택 기여도가 7.2%에
불과해(EF1%은 75%) 사실상 편향에 면역이라, 2-of-3 규칙에서 거의 자동 통과했다.

그래서 문턱 숫자를 올리는 대신 판정 근거를 바꿨다. 통과하려면 같은 라이브러리를
닮지 않은 구조에 도킹한 대조군보다 **통계적으로 유의하게** 나아야 한다.
대조군이 없으면 이 비교가 불가능하므로 ABSTAIN이다.

벤치마크 회수도 이제 판정에 들어간다. 이전에는 경고 문자열만 붙이고 verdict에
손대지 않아서, MET이 승인약 0/4인데도 PASS로 나왔다.

근거: Chaput et al. 2016, *J Cheminform* 8:56 — 편향 타깃을 제거하자 성공
타깃이 Glide 5/47, Gold 4/47로 떨어졌다.

## 평가셋과 스크리닝셋은 다른 집합이다

2026-10-23 이전에는 구분이 없었다. 그래서 decoy 전체가 채점의 음성으로 쓰이면서
동시에 후보 추출원이었고, **EPAS1·MET 양 타깃 모두 상위 20 후보가 전원 decoy
라벨로 나왔다** — 파이프라인이 제 성능을 채점할 때 음성으로 센 바로 그 화합물을
후보로 내놓고 있었다는 뜻이다. EF1%가 천장에 닿으면 후보가 0개가 되므로, 후보는
지표의 오차 안에만 존재했다.

지금은 `--n-screen N`으로 평가셋과 겹치지 않는 별도 집합을 더한다. 기본값 0 —
측정에는 screen이 필요 없고, 켜면 그만큼 도킹 비용이 늘어난다.

**분할 이전에 나온 후보 목록은 전부 무효다.**

## 실행

GitHub → Actions → **Joi_bio pipeline** → Run workflow → gene에 `EPAS1` 입력.
`all`을 넣으면 10개 타깃 전체를 돈다.

대조군 없이 돌리면 게이트가 ABSTAIN을 낸다. 판정을 받으려면 control 워크플로를
함께 돌리고 `--controldir`을 넘겨야 한다.

로컬에서 돌리려면 conda 환경이 필요하다. `pip install vina`는 Boost 1.83+의
deprecated 헤더 때문에 빌드가 깨지므로 conda-forge 바이너리를 쓴다.

```bash
micromamba env create -f environment.yml && micromamba activate joi-bio

python -m core.structure.fetch        --gene EPAS1
python -m modules.small_molecule.library --gene EPAS1 --n-decoys 2000
python -m modules.small_molecule.dock    --gene EPAS1
python -m core.validation.gate        --gene EPAS1
python -m modules.small_molecule.admet   --gene EPAS1
python -m core.report.build
```

## 타깃 10개

**신장암(RCC)** EPAS1(HIF-2α), MET, VHL, CA9, AXL
**기전·CKD** SLC5A2(SGLT2), NLRP3, KEAP1, APOL1, KCNJ1(ROMK)

선정 기준은 ① PDB 실험구조 존재 ② ChEMBL 활성 데이터 존재 ③ 신장 질환 연관성.
근거와 리스크는 `config/targets.yaml`에 적어 두었다.

## 미리 예상되는 실패

10개 전부 통과를 기대하면 안 된다. 3~5개가 통과하면 1차로는 성공이다.

- **APOL1** 실험구조가 부족해 AlphaFold 모델 + blind docking이 된다. FAIL이
  정상적인 결과다.
- **KEAP1, VHL** PPI 타깃이라 리지드 도킹으로는 농축도가 낮게 나오기 쉽다.
- **CA9** Zn²⁺ 배위를 Vina 스코어링이 과소평가한다.

어느 타깃이 왜 실패했는지가 다음 단계 설계의 자산이다.

## 방법의 한계

리지드 수용체 도킹이며 측쇄 유연성과 유도 적합을 반영하지 않는다. 리간드
프로토네이션은 ChEMBL 표기 그대로이고 pH 7.4 기준으로 재계산하지 않는다.
ADMET은 경험적 rule이며 학습된 예측 모델이 아니다. 출력 화합물은 전부
`candidate_for_testing`이고, 실험 검증 전에는 히트가 아니다.
